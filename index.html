XTTS-Server-MacOS-Guide

A guide, not a program. This repository holds no server code of its own. It records, from the author's own Mac, how to run the upstream xtts-api-server on Apple Silicon, following the SillyTavern XTTS notes. It assumes Homebrew, a zsh shell, and an Apple Silicon machine. Use a Chromium based browser, because other browsers gave trouble with the server page.

Read the guide on GitHub Upstream xtts-api-server

Station one: the yard prepared

Make a folder called xtts, enter it, and create two folders inside it, speakers and output, because the server expects speaker files in the first and puts generated audio in the second. Then take the Homebrew route in its given order:

mkdir xtts
cd xtts
mkdir speakers
mkdir output
brew install miniconda
conda init zsh
source ~/.zshrc
conda create -n xtts
conda activate xtts
conda install python=3.10

Station two: the load taken on

pip install xtts-api-server pydub
pip install torch==2.1.1 torchaudio==2.1.1 torchvision --index-url https://download.pytorch.org/whl/cu118
python -m xtts_api_server --streaming-mode-improve

Warning, in the guide's own terms: the printed torch line pulls from the cu118 CUDA wheel index, which does not match a Mac or Apple Silicon. A Mac needs the default torch install instead, and that corrected Mac step was not run or tested in the guide's latest pass.

The route ends where the whole road aims: python -m xtts_api_server --streaming-mode-improve, starting the server with its improved streaming mode.

Station three: the second road, Docker

Install Docker Engine, clone the upstream xtts-api-server repository, enter its docker folder, and build for this machine's architecture, because no ready made image is pulled:

git clone https://github.com/daswer123/xtts-api-server.git
cd docker
docker build --platform linux/arm64 -t xtts-api-server-arm .

An honest gap: the guide then prints a host start line, python -m xtts_api_server --streaming-mode --use-cache -ms local -d cpu, which starts the local install rather than the container just built. The guide gives no container start command at all. That gap is left visible here as a gap.

Footer station: the limits ledger
